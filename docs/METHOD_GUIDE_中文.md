# 手术阶段识别方法学习指南

本文讲解本项目的手术阶段识别方法：每一步做什么计算，用什么网络结构，为什么这样设计。它是学习用的说明。全部实验的原始记录在 [TEMPORAL_DESIGN_中文.md](TEMPORAL_DESIGN_中文.md)，数据处理的细节在 [DATASET.md](DATASET.md)。

文中的数字都来自 12 个有标注视频上的固定 4 折交叉验证。它们是开发阶段的估计，不是独立测试成绩。最终方案的数字来自 2026-09-27 的运行 `advanced_cv_01`（随机种子 42）。

## 第一档 一页总览

### 1.1 任务

手术是腹腔镜乙状结肠切除术。输入是手术视频，30 fps（每秒 30 帧），分辨率 1280×720。输出是每个时刻属于哪个手术工程。本文把"工程"也叫"阶段"。工程共 13 类。镜头在体外时，画面被主办方涂黑，这些时刻记为 x。

| 编号 | 工程内容 |
|---|---|
| 0 | 手术开始到工程开始前 |
| 1 | 骶岬以下（尾侧）的内侧游离，正中右侧的系膜切除 |
| 2 | 骶岬以上（头侧）、IMA/SRA 右侧的内侧游离 |
| 3 | IMA 处理 |
| 4 | IMA/SRA 左侧的内侧游离 |
| 5 | SDJ 以上（头侧）的外侧游离 |
| 6 | SDJ 以下（尾侧）的外侧游离，正中左侧的系膜切除 |
| 7 | 预定切离线上的直肠系膜处理 |
| 81 | 直肠切离到吻合之间、不属于 82 和 83 的场景 |
| 82 | 直肠切离 |
| 83 | 吻合 |
| 9 | IMV（LCA）处理 |
| 13 | 工程结束到手术结束 |
| x | 体外，画面涂黑，不属于上面 13 类 |

缩写：IMA 是肠系膜下动脉，SRA 是直肠上动脉，IMV 是肠系膜下静脉，LCA 是左结肠动脉，SDJ 是乙状结肠与降结肠的交界处。工程编号不代表先后顺序。例如工程 9 在视频 03、09、10、13 里紧接在工程 4 之后，在视频 01 和 05 里出现在 81、82 之后。

比赛（第 6 回 JSCAS AI Challenge）有两条赛道：

| 赛道 | 要做什么 | 指标 |
|---|---|---|
| Basic | 给每张 1 fps 抽帧图片（不含体外帧）一个工程标签 | 准确率 |
| Advanced | 把整段视频切成工程段，写出每段的起始帧号，x 段也要写 | 段级 F1@0.75，4 个测试视频的 TP、FP、FN 先合计，再算一个 F1 |

数据共 16 个视频。12 个有标注，用于训练和验证：01、03、04、05、06、08、09、10、12、13、14、16。4 个是测试视频：02、07、11、15，没有标注，不能用于训练。

### 1.2 方法一句话

一个在大量手术视频上预训练过的视觉模型把每秒一张图变成特征，本项目不再训练这个模型。线性分类头给出每秒的工程概率。一个小型时序网络读整段视频，修正这些概率。最后按训练视频总结出的手术流程规则，精确地选出最合理的标签序列。

### 1.3 流程图

```
30 fps 原视频
  │ ① 官方脚本每秒抽一帧，去掉体外黑帧
  ▼
1 fps 图片（每个视频 4,719 到 7,501 张）
  │ ② 冻结的 SurgeNetXL DINOv2-B/14，输入 336×336
  ▼
每张图一个 1536 维特征
  │ ③ 按视频标准化（只用本视频自己的统计量，不用标签）
  ▼
  │ ④ 交叉拟合的线性分类头
  ▼
每秒 13 个工程的对数概率（"逐帧证据"）
  │ ⑤ 按时间排成整段视频的序列，加上 32 个主成分和 6 个时间标志
  │ ⑥ 时序网络：膨胀卷积 + 全局自注意力 + 细化级，5 个随机种子取平均
  ▼
每秒 13 个工程的对数概率（"看过整段视频的判断"）
  │ ⑦ 约束解码：先后规则 + 单段规则 + 最短块长，精确 Viterbi
  ▼
每秒一个工程标签
  ├─ Basic：直接作为每张图片的答案
  └─ Advanced：展开到 30 fps，补上 x 段，切成段
```

### 1.4 结果

| 读法 | 帧准确率（Basic） | 段级 F1@0.75（Advanced，官方合计口径） |
|---|---:|---:|
| 只用逐帧线性头 | 76.97% | — |
| 加时序网络 | 88.97% | 0.690 |
| 再加先后规则和单段规则 | 89.32% | — |
| 再加最短块长（最终方案） | 89.38% | 0.729 |

表中"—"表示这两种读法的逐帧输出没有保存，没有按官方合计口径重算。按逐视频平均的口径，它们分别是 0.035 和 0.706。

测试集只有 4 个视频，分数波动很大。在 12 个验证结果里任取 4 个视频组合（共 495 种），帧准确率的 90% 区间是 86.5% 到 92.2%，Advanced F1 的 90% 区间是 0.66 到 0.79。

## 第二档 每个模块做什么，为什么

### 2.1 抽帧（模块 ①）

做什么：用主办方的脚本，每秒取一帧，即原视频的第 0、30、60……帧，并去掉体外的黑帧。12 个视频共得到 74,430 张有效图片。

为什么：Basic 赛道的输入就是这些 1 fps 图片。主办方 FAQ 规定，Basic 推理时不能读取视频文件本身。所以整个方法只建立在 1 fps 图片上。

### 2.2 冻结的视觉特征（模块 ②）

做什么：每张图缩放到 336×336，送进 DINOv2-B/14 视觉模型，取出一个 1536 维的特征向量。模型权重来自 SurgeNetXL。SurgeNetXL 用 DINOv2 自监督方法在大量外科手术视频帧上预训练。自监督是指训练不需要人工标签。本项目不训练这个模型，只用它提取特征，所以叫"冻结"。

为什么：有标注的手术只有 12 台。直接训练或微调这么大的模型，它会记住"这是哪台手术"，而不是"这是哪个工程"。实测用 LoRA 微调（只训练少量附加参数的方法）没有带来提升。冻结特征只需要提取一次，后面所有实验都只在特征上运行，速度很快。

### 2.3 按视频标准化（模块 ③）

做什么：对每个视频，用它自己所有帧的均值和标准差，把特征的每一维变成 z 分数（减去均值再除以标准差）。

为什么：不同手术的整体画面有差异，例如患者、镜头、白平衡、出血量。这种差异让同一个工程在不同视频里的特征整体偏移。减去视频自己的均值，可以去掉大部分这种偏移。这一步不用标签，所以测试视频可以用完全相同的方式计算。

### 2.4 交叉拟合的线性分类头（模块 ④）

做什么：训练一个线性分类器，把 1536 维特征变成 13 个工程的概率。关键是"交叉拟合"：每个视频的概率，永远来自一个没有见过这个视频的分类器。

为什么：分类器在它训练过的视频上准确率约 96%，在新视频上只有约 77%。后面的时序网络要学会修正分类器的错误。如果训练时给它 96% 准确的概率，它会学到"概率基本都对"，到新视频上就失效。交叉拟合让训练时看到的错误，在数量和样子上都和测试时一样。

### 2.5 时序网络的输入（模块 ⑤）

做什么：把一个视频所有秒的信息按时间排成序列。每秒 51 个数：13 个工程概率、32 个特征主成分、6 个时间标志。时间标志的例子有"这一秒没有图片""在长体外段之后""手术进行到百分之几"。

为什么：单张图只能看到当下，而一个工程会持续几分钟到几十分钟，前后的画面能大幅减少误判。只给概率会丢掉分类器没有学到的信息。给全部 1536 维又太多，因为每折只有 9 条训练序列。实测 32 个主成分最好。

### 2.6 时序网络（模块 ⑥）

做什么：一个约 30 万参数的小网络。膨胀卷积让每一秒看到前后各约 17 分钟。一层自注意力让任何时刻都能参考整台手术。第二级网络再修正第一级的输出。最后把 5 个不同随机种子训练的网络取平均。

为什么：每折只有 9 条训练序列，网络必须小，还需要大量数据增广：随机变速、裁剪、加噪声、遮挡，以及模拟分类器在新视频上的整段错误。自注意力比较的是同一视频内两个时刻的内容，视频之间的整体差异不影响它。

### 2.7 约束解码（模块 ⑦）

做什么：从训练视频的标注读出三类规则。然后在满足全部规则的标签序列里，找网络对数概率总和最大的那一条。三类规则各举一例：IMA 处理（3）开始后，不再回到工程 2。工程 3 只有连续一段。工程 9 的每一段至少 224 秒。

为什么：有些事实在每台手术都成立。网络大多数时候遵守它们，但不总是。精确解码只在网络违反规则的地方改动标签，而且没有需要调整的参数。最短块长去掉几秒到几十秒的碎片段，这对 Advanced 的段级指标有直接帮助。

### 2.8 无泄漏的评估（模块 ⑧）

做什么：固定 4 折，每折 9 个视频训练，3 个视频验证。分类头、主成分、网络的训练轮数、规则，全部只用该折的 9 个训练视频得到。验证视频只在最后被预测一次。

为什么：只有 12 个视频，任何"看验证集挑参数"的做法都会让分数虚高。实测在验证视频上直接挑超参数，单折会虚高约 2 个点。

## 第三档 每个模块的计算细节

本档用以下记号：$N$ 是图片数，$T$ 是一个视频时间线的秒数（含空洞），$K=13$ 是工程类数。

### 3.1 数据与时间线

原始数据是 16 个 MP4 视频和 12 个标注 CSV。标注 CSV 每行是"起始帧号, 工程"，一个工程从本行的起始帧持续到下一行的起始帧。最后一行的 `e` 表示视频结束，不计分。

抽帧用主办方的 `extract_frames.py`，参数是每秒一帧、忽略 x。另外排除 4 张整图 RGB 值都不超过 1 的近黑帧。它们有工程标签，但画面是黑的。结果是 92,061 张 PNG，其中有效图片 74,430 张，体外 x 图片 17,627 张。

时间线（`timeline.py`）：秒号等于帧号除以 30。从一个视频的第一张图到最后一张图，每秒占一格。没有图片的格叫"空洞"，它们就是体外的时间。每个视频都恰好有一段很长的空洞（880 到 1,547 秒），叫"长空洞"，对应取出标本和体外操作。其它空洞都不超过 104 秒。长空洞之后，12 个视频都只出现工程 81、83、13。

4 折划分写在 `configs/cv4_reference.json`：第 1 折验证 01、10、14，第 2 折 04、06、13，第 3 折 05、12、16，第 4 折 03、08、09。划分只按各工程的帧数平衡，不看任何模型结果。

### 3.2 特征提取（DINOv2-B/14）

预处理（`runtime.py`）：用双三次插值把 1280×720 的图缩放到 336×336，不保持宽高比。然后转成 0 到 1 的数，再按 ImageNet 的均值 (0.485, 0.456, 0.406) 和标准差 (0.229, 0.224, 0.225) 归一化。

网络是 ViT-B/14（Vision Transformer，Base 规模，patch 边长 14 像素）：

```
336×336 图像
  │ 切成 24×24 = 576 个 14×14 的小块（patch），每块线性投影成 768 维
  │ 前面加 1 个 CLS token（汇总全图信息的特殊向量）
  ▼
577 个 768 维向量
  │ 12 层 Transformer（每层：多头自注意力 + MLP）
  │ 最终 LayerNorm
  ▼
577 个 768 维输出向量
```

本项目从最后一层取两样东西，拼成 1536 维：

$$
f = \Big[\, h_{\mathrm{CLS}} \;\Big\|\; \frac{1}{576}\sum_{i=1}^{576} h_i \,\Big] \in \mathbb{R}^{1536}
$$

$h_{\mathrm{CLS}}$ 是 CLS token 的输出，偏重全图的语义。$h_i$ 是第 $i$ 个 patch token 的输出，它们的平均保留更多局部内容，例如器械和组织。这是 DINOv2 论文做线性探测时的做法。

冻结和校验：提取时不计算梯度，提取前后检查模型权重的摘要没有变化。特征提取一次后缓存为 `tokens.pt`，大小 74,430 × 1536。每次加载时，CLS 部分都与早期只存 CLS 的缓存逐行比对，误差容限 $10^{-5}$，实测逐位相等。

代码：`surgenet_dino/temporal/tokens.py`（命令 `cache-tokens`），`surgenet_dino/model.py`，`surgenet_dino/registry.py`。

### 3.3 按视频标准化

对视频 $v$ 的每一帧特征 $f_t$：

$$
z_t = \frac{f_t - \mu_v}{\sigma_v}
$$

$\mu_v$ 和 $\sigma_v$ 是视频 $v$ 所有帧在每一维上的均值和标准差（逐维计算，1536 个均值和 1536 个标准差）。这个做法和语音识别里的倒谱均值方差归一化相同，目的是去掉每段录音的整体偏移。

更强的校正试过，但都没有用。按视频做全协方差白化，逐帧头从 76.9% 降到 61% 到 73%。投影掉"同一工程在不同视频间的差异方向"（NAP），没有变化。原因是一个视频内部特征的变化主要来自工程之间的差别，校正得越强，越会把区分工程的信息一起抹掉。

代码：`emissions.per_video_zscore`。

### 3.4 交叉拟合的线性分类头

结构：Dropout(0.1) → Linear(1536 → 13)。对标准化后的特征 $z_t$：

$$
\hat{p}_t = \mathrm{softmax}(W z_t + b), \quad W \in \mathbb{R}^{13\times 1536},\ b \in \mathbb{R}^{13}
$$

训练：交叉熵损失，标签平滑 0.05。标签平滑是指把目标分布从"正确类 1，其余 0"改成"正确类 0.95 + 0.05/13，其余各 0.05/13"，让模型不过分自信。优化器 AdamW，学习率 $3\times10^{-4}$，权重衰减 0.05（只对权重，不对偏置），batch 64，固定训练 5 轮。轮数固定，不看任何验证数据，也没有 early stop。

交叉拟合的具体做法：

```
某一折：训练视频 A…I（9 个），验证视频 X、Y、Z（3 个）

A 的概率  ← 用 B…I 训练的头（留一视频，leave-one-video-out）
B 的概率  ← 用 A、C…I 训练的头
…
I 的概率  ← 用 A…H 训练的头
X、Y、Z 的概率 ← 用 A…I 全部训练的头（第 10 个头）
```

每个视频的概率都来自一个没有见过它的头。代码里有一个"账本"，记录每个视频的概率来自哪个头、那个头用哪些视频训练，并在运行时断言没有泄漏。

为什么一定要这样做：头在自己训练过的视频上约 96%，在新视频上约 77%，差距约 20 个点。这个差距从第 1 轮训练就存在，多训少训都改变不了，它来自视频之间的分布差异。时序网络在训练时必须看到"77% 水平"的输入，测试时才不会失效。逐帧头本身在 4 折上的准确率是 76.97%。

代码：`emissions.stacked_emissions`，`emissions.fit_head_fixed`，`surgenet_dino/head.py`。

### 3.5 时序网络的输入

每个视频变成一个 $51 \times T$ 的矩阵，每列是一秒：

| 行数 | 内容 | 计算方法 |
|---:|---|---|
| 13 | 逐帧对数概率 | $e_{t,c} = \max(\log\hat{p}_{t,c},\,-10)\,/\,5 + 1$，范围约 −1 到 1 |
| 32 | 特征主成分 | 见下面的公式 |
| 6 | 时间标志 | 本秒没有图片，在长空洞内，在长空洞之后，相对进度 $t/(T-1)$，已过小时数 $t/3600$，长空洞结束后的小时数 |

主成分（PCA）只在该折的训练视频上拟合。设 $m$ 是训练帧的均值，$B$ 是协方差矩阵前 32 个特征向量组成的 1536×32 矩阵，$s$ 是对应特征值的平方根：

$$
u_t = \mathrm{clip}\!\left(\frac{(z_t - m)\,B}{s},\ -6,\ 6\right) \in \mathbb{R}^{32}
$$

没有图片的秒，概率行和主成分行都是 0，"本秒没有图片"标志是 1。

训练标签（`timeline.label_track`）：有图片的秒用真实标签。一个空洞两侧的标签相同时，空洞用这个标签填上。两侧不同的空洞和长空洞记为 −1，不计入损失。

为什么用 32 个主成分：第 3 折上试过 1、16、64、128 个，32 最好，更多反而更差，因为网络只有 9 条训练序列。

为什么需要时间标志：长空洞在每台手术都有，而且之后只会出现 81、83、13，它是很强的时间锚点。相对进度也能提示"手术进行到哪一步"。

代码：`tcn.build_inputs`，`tcn.fit_pca`，`timeline.py`。

### 3.6 时序网络的结构

```
输入 [51 × T]
  │ 输入 dropout 0.15
  ▼
┌────────────── 预测级 ──────────────┐
│ 1×1 卷积 51 → 64                    │
│ 10 个膨胀残差块，膨胀 1, 2, 4, …, 512 │
│   每块：x + Dropout(1×1卷积(GELU(3×1膨胀卷积(LayerNorm(x))))) │
│ 全局上下文（以残差加回）：            │
│   平均池化到 1/16 长度                │
│   → 1 层自注意力（4 头，相对位置偏置）│
│   → 线性插值回长度 T                 │
│ LayerNorm → 1×1 卷积 64 → 13         │
└────────────────────────────────────┘
  │ softmax（第一组输出，也计入损失）
  ▼
┌────────────── 细化级 ──────────────┐
│ 1×1 卷积 13 → 48                    │
│ 10 个膨胀残差块（同上）              │
│ LayerNorm → 1×1 卷积 48 → 13         │
└────────────────────────────────────┘
  ▼
输出 [13 × T]（预测时只用细化级的输出）
```

参数量：共 299,786 个。预测级 204,301 个，其中自注意力部分 33,600 个。细化级 95,485 个。

膨胀卷积：卷积核长 3，但相邻两个取样点之间隔 $d$ 秒，$d$ 叫膨胀率。10 层的膨胀率依次是 1, 2, 4, …, 512，所以一级的卷积部分能看到的范围（感受野）是：

$$
R = 1 + (3-1)\sum_{i=0}^{9} 2^i = 1 + 2 \times 1023 = 2047\ \text{秒}
$$

也就是每一秒能看到前后各约 17 分钟。

自注意力：先把序列平均池化到 1/16 长度，例如 7,000 秒变成 438 个位置。在这些位置上做一层 4 头自注意力：

$$
\mathrm{Attn}(H)_i = \sum_j \mathrm{softmax}_j\!\left(\frac{q_i \cdot k_j}{\sqrt{d}} + b(i-j)\right) v_j
$$

$q, k, v$ 是每个位置的查询、键、值向量，$d=16$ 是每个头的维数。$b(i-j)$ 是相对位置偏置：按位置差的正负和对数大小分到 32 个桶里，每个桶每个头学一个数，初始为 0，最远区分到 512 个位置。网络不使用绝对位置编码。注意力之后接一个两倍宽度的 MLP，再线性插值回原长度，加到卷积的输出上。

归一化：每一秒对 64 个通道做 LayerNorm，不用 BatchNorm。原因是训练时一个 batch 只有一条序列，而且文献指出 BatchNorm 在视频时序模型里有已知问题。

为什么在 1/16 分辨率上做注意力：全分辨率注意力的计算量和显存与 $T^2$ 成正比，$T$ 约 7,000 时太大。1/16 之后的几百个位置，已经足够表达"手术进行到哪一步"。

为什么分两级：这是 MS-TCN 的做法。细化级以预测级的概率为输入，专门修正碎片和抖动。它在预测级不准确的输出上训练，所以学到的是"怎么修"。

代码：`tcn.PhaseTCN`，`tcn.Stage`，`tcn.DilatedBlock`，`tcn.GlobalContext`，`tcn.SelfAttention`，`tcn.RelativeBias`。

### 3.7 训练：损失、增广、优化器、多种子

损失对两级输出 $s \in \{1, 2\}$ 都计算，然后相加：

$$
\mathcal{L} = \sum_{s=1}^{2}\left[\mathrm{CE}_{0.05}\big(y,\ \hat{y}^{(s)}\big) + 0.15 \cdot \frac{1}{TK}\sum_{t,c}\min\!\Big(\big(\log p^{(s)}_{t,c} - \mathrm{sg}(\log p^{(s)}_{t-1,c})\big)^2,\ 16\Big)\right]
$$

第一项是带标签平滑 0.05 的交叉熵，标签为 −1 的秒不计入。第二项是平滑项：惩罚相邻两秒的对数概率变化，变化过大时截断在 16，避免真正的工程切换被过度惩罚。$\mathrm{sg}$ 表示不对这一项回传梯度。这也是 MS-TCN 的做法。

数据增广：每次取一条训练序列时，依次随机做以下处理。

1. 分段变速：把序列分成 4 段，每段独立拉伸到原长度的 0.7 到 1.4 倍。
2. 随机裁剪：以 50% 的概率截取一个窗口，长度至少是全长的一半，窗口里有标签的秒不能少于 25%。
3. 概率噪声：13 个对数概率通道加标准差 0.5 的高斯噪声。
4. 混淆扰动：随机 0 到 3 段，每段 10 到 120 秒。把这段的主要真实工程的对数概率压低 3，把一个"新视频上常与它混淆的工程"抬高 3。混淆对象按交叉拟合头的混淆矩阵抽样，用来模拟分类器在新视频上的整段系统性错误。
5. 遮挡：随机 1 到 2 段，每段 18 到 300 秒，把概率和主成分清零，并标为"没有图片"，模拟体外和缺帧。
6. 以 30% 的概率把 32 个主成分全部清零，迫使网络也学会依赖概率通道。

优化器：AdamW，学习率 $5\times10^{-4}$，权重衰减 0.01，梯度裁剪（梯度范数超过 1.0 时按比例缩小）。每一步只用一条序列，一轮把 9 条训练序列各走一次。

多种子集成：同一配置用 5 个随机种子训练 5 个网络。预测时对细化级输出的对数概率取平均，等价于对概率取几何平均：

$$
\log \bar{p}_t = \frac{1}{5}\sum_{k=1}^{5} \log p^{(k)}_t
$$

实测 5 个种子的集成比单个种子高 1 到 2 个点。在第 3 折上，10 个种子比 5 个种子再高约 0.3 个点，代价是训练时间加倍，没有采用。

代码：`tcn.sequence_loss`，`tcn.augment`，`tcn.fit_tcn`，`tcn.predict_tcn`，`tcn.refit`。

### 3.8 训练轮数怎么定：内层交叉验证

候选轮数是 10、20、30、40、50、60。轮数只用训练视频来选：

1. 把该折的 9 个训练视频再分成 3 个内层折，每个内层折留出 3 个视频。
2. 每个内层折都从头做一遍：交叉拟合头、PCA、5 个种子的网络。训练到 60 轮，在每个候选轮数记录留出视频的预测。
3. 把 9 个训练视频的内层预测合起来，算每个候选轮数的准确率，取最高的一个，并列时取较小的轮数。
4. 用全部 9 个训练视频，按选定的轮数重新训练 5 个网络，预测 3 个验证视频。

例子：第 1 折的内层准确率是 10 轮 81.3%，20 轮 86.1%，30 轮 87.3%，40 轮 87.3%，50 轮 87.8%，60 轮 87.5%，所以选 50 轮。最终运行里 4 折选的轮数是 50、60、60、60。

为什么不直接看验证集的损失来停：验证集只有 3 个视频，曲线上下抖动约 1 个点。用它挑停止时刻，等于在验证集上挑最好的一刻，数字会偏高。学习曲线显示，网络在 20 轮后进入平台，训练到 120 轮也没有下降，所以多训几轮也没有害处。

代码：`tcn.inner_cv`，`tcn.common_epoch`，`tcn.checkpoint_epochs`，`folds.make_inner_groups`。

### 3.9 约束解码

规则的读取（`constraints.learn_rules`）：只读该折 9 个训练视频的标签序列，只保留在每一个训练视频里都成立的规则，而且至少有一个视频同时包含相关的工程，避免空洞的规则。

| 规则 | 含义 | 最终运行里每折的数量 |
|---|---|---|
| 先后 a → b | 每个训练视频里，a 的最后一秒都在 b 的第一秒之前。解码时 b 一旦开始，a 不能再出现 | 51、51、53、54 条，例如 2 → 3，0…7 → 81，82 → 83 |
| 单段 m | 每个训练视频里，m 都只有连续一段。解码时离开 m 后不能再回到 m | 3、6、82、9、13，第 3 折另有 83 |
| 最短块长 m | 训练视频里 m 最短的一段有多少秒（按有图片的秒计） | 每个工程一个数，见下面的例子 |

第 1 折的最短块长（秒）：0 为 162，1 为 38，2 为 72，3 为 54，4 为 51，5 为 76，6 为 56，7 为 66，81 为 3，82 为 12，83 为 15，9 为 253，13 为 95。

解码目标：在满足全部规则的所有标签序列 $y$ 中，找对数概率总和最大的一条：

$$
\hat{y} = \arg\max_{y}\ \sum_{t} \log \bar{p}_t(y_t) \quad \text{约束：} y \text{ 满足该折的全部规则}
$$

这个最大化用 Viterbi 动态规划精确求解。状态是"已经开始过的受约束工程集合 $M$"加"当前工程 $q$"。受约束的工程是出现在先后规则右侧或单段规则里的工程，4 折都是 3、4、6、7、81、82、83、9、13 这 9 个，所以集合有 $2^9 = 512$ 种，状态数是 512 × 13。设 $s_t(q) = \log\bar{p}_t(q)$，$d_q$ 是 $q$ 的最短块长：

$$
V_t(M, q) = \max\Big\{\ \underbrace{V_{t-1}(M, q) + s_t(q)}_{\text{继续当前块}},\ \ \underbrace{\max_{q' \ne q,\ M'} V_{t-d_q}(M', q') + \sum_{u=t-d_q+1}^{t} s_u(q)}_{\text{进入 }q\text{，一次走完 }d_q\text{ 秒}}\ \Big\}
$$

进入 $q$ 时要满足两个条件。第一，$M$ 里没有任何会禁止 $q$ 的已开始工程。第二，如果 $q$ 是单段工程，它不能是第二次进入。进入后 $M = M' \cup \{q\}$。块内得分 $\sum s_u(q)$ 用前缀和一次算出，所以最短块长不增加状态数。最后从得分最高的状态回溯，得到整条标签序列。每个视频在 CPU 上约 5 秒。

几个性质：

1. 网络输出不违反任何规则时，结果就是逐秒取概率最大的类。
2. 没有转移概率，没有时长分布，没有可调参数。规则全部是训练视频里的观测事实。
3. 最短块长全设为 1 时，结果和只用先后、单段规则时逐秒相同。
4. 遇到太短的块，解码器在"删掉它"和"把它补长到最短块长"之间选总代价小的一种。所以标签正确、只是偏短的块会被补长，而不是被删掉。

写出概率时，被解码改动的那些秒，把网络原来最高类的概率和解码类的概率互换。这样每一行仍是一个概率分布，而且最大值就是解码结果。

代码：`constraints.py`（`learn_rules`，`training_rules`，`decode`，`apply_rules`）。

### 3.10 评估指标

Basic 的准确率在所有有图片的秒（即 1 fps 的非 x 帧）上计算：

$$
\mathrm{Acc} = \frac{1}{N}\sum_{i=1}^{N} \mathbb{1}[\hat{y}_i = y_i]
$$

本项目还报告宏 F1（13 类各自的 F1 的平均）和最差视频的准确率。

Advanced 的段级 F1@0.75（Lea 等 2017 年提出）按以下步骤计算：

1. 把 30 fps 的标签序列切成段。一段是同一个标签的最长连续片段，x 也会成段。
2. 对每个预测段，找同标签、交并比（IoU）最大的真实段。IoU 是两段交集的帧数除以并集的帧数。IoU 不低于 0.75，并且这个真实段还没有被匹配过，就记一个 TP（正确的段）。
3. FP 是预测段数减去 TP，FN 是真实段数减去 TP。
4. 4 个视频的 TP、FP、FN 先各自求和，再算一个 F1：

$$
F1 = \frac{2\,TP}{2\,TP + FP + FN}
$$

本地如何模拟官方评分（`advanced.py`）：x 段直接取真值，因为主办方说明 x 帧被涂黑，可以从画面精确检出。其它每一帧取时间上最近的那张 1 fps 图片的预测，也就是以相邻两个抽帧的中点为分界。最终方案合计 TP 306、FP 104、FN 124。

仓库里另有一列 `f1_at_75`，它在跳过体外段的 1 fps 序列上计算，`81 | x | 81` 会被合成一段。它不等于官方口径。Advanced 以 `advanced_f1_at_75` 为准。

噪声的大小：同一配置换随机种子，帧准确率相差约 0.34 个点。同种子重跑只差 0.01 到 0.04 个点。所以比较两个方案时，要在相同种子下配对比较，最好比较多个种子。

代码：`workflows.py`（`summary_row`，`segment_counts`，`f1_score`），`advanced.py`。

### 3.11 可选：运动特征（只限 Advanced）

计算（`tools/motion_features.py`）：对每个 1 fps 帧 $f$，解码 30 fps 原视频里 $[f-15, f+15)$ 共 30 帧，算 16 个非负的量：

1. 128×72 灰度图上相邻帧差的均值、最大值、标准差，共 3 个。
2. 320×180 上每隔 3 帧算一次 DIS 稠密光流，得到平均幅值、最大幅值、平均流向量的幅值（镜头整体运动）、去掉平均向量后的残差幅值（局部运动，例如器械），共 4 个。
3. 3×3 网格里每格的光流幅值，共 9 个。

这 16 个量取 $\log(1+x)$，再按视频标准化，作为时序网络的 16 个额外输入通道（51 维变成 67 维）。分类头和 PCA 不受影响。

规则：主办方 FAQ Q5(d) 规定 Basic 推理时不能使用评价视频文件本身，所以运动特征只能用于 Advanced。

实测：最初记录的 +0.4 个点是在一个增广 bug 下测得的。修复后（种子 42 配对），帧准确率 89.38% 变成 89.43%，Advanced F1 0.729 变成 0.724，没有提升。最终方案在两条赛道都不使用它，代码保留为可选项（`cv --motion`）。

## 第四档 优化历程

### 4.1 每一步加了什么，提升多少

| 步骤 | 帧准确率 | 加入的东西和思路 |
|---|---:|---|
| 起点：逐帧线性头，只用 768 维 CLS | 76.69% | 单张图的信息上限 |
| 加马尔可夫链 | 84.24% | 用相邻时刻的转移概率利用时间顺序，提升约 7.5 个点 |
| 加按视频标准化和交叉拟合 | 86.19% | 去掉视频整体偏移，并让训练和测试时的输入误差一致 |
| 用时序卷积网络代替马尔可夫链 | 88.66% | 学到更长、更复杂的上下文，不再需要马尔可夫链 |
| CLS 加 patch 均值，加全局注意力，5 个种子 | 88.79% 到 88.97% | 平均精度持平，最差视频从 78.0% 升到 82.5%，结构更稳定 |
| 加先后规则和单段规则的约束解码 | 89.17% 到 89.32% | 修掉违反手术流程的输出，在三次独立运行上都提高 0.30 到 0.34 个点 |
| 加最短块长（最终方案） | 89.38% | 修掉碎片段，帧准确率持平，Advanced F1 提高约 0.02 |

这些步骤是在不同时间、不同运行里测得的。同一步的数字有 ±0.3 个点左右的运行间差异，所以表中有些步骤写的是范围。

### 4.2 每一步为什么有效

时间顺序是最大的增益。单张图只能达到约 77%，因为很多工程的画面很像，例如内侧游离和外侧游离都在切开系膜。看前后几分钟，就能知道手术进行到哪一步。

按视频标准化和交叉拟合解决的是"新视频长得不一样"的问题。分类器在见过的视频上 96%，在新视频上 77%。标准化减少整体偏移。交叉拟合让时序网络在训练时就面对 77% 水平的输入。

时序网络比马尔可夫链好，因为马尔可夫链只看相邻两秒，而时序网络一次看几十分钟，还能学到"进行到哪一步"这种整体信息。时序网络之后再接马尔可夫链，反而从 88.66% 降到 87.93%。

约束解码有效，是因为手术流程里有不可逆的事件。例如直肠切离相关场景（81）一旦开始，0 到 7 就不会再出现。网络偶尔会违反，例如在视频 14 里，网络在真正的 81 开始前 3 分钟判成 81，随后又回到 7。约束解码把这类错误改回来。

最短块长针对 Advanced 的段级指标。帧准确率里，几秒的碎片只算几秒的错。段级 F1 里，每个碎片都是一个 FP，还把一个真实段切成两段。贪心地删除短块会把标签正确但偏短的块也删掉，帧准确率下降 0.1 到 0.8 个点。精确解码可以选择补长，所以帧准确率没有下降。

### 4.4 学到的经验

1. 逐帧证据的提升不一定能传到时序网络。逐帧头的提升哪怕有 6 个点（上下文头），网络也没有变好。时序网络本来就在整合上下文。
2. 单折的结果会骗人。第 3 折上 +1.3、+1.6、+0.5 的提升，到 4 折合并时都消失了。
3. 换随机种子的波动约 0.34 个点。小于这个量的差别，要用多个种子配对确认。
4. 直接在验证视频上挑超参数，单折会虚高约 2 个点。所以所有选择都在训练视频内部完成。
5. 学习曲线显示，训练手术从 5 台到 7 台到 9 台，帧准确率 87.7%、88.6%、89.4%，还在上升，每多一台约 +0.4 个点。目前最大的杠杆是更多有标注的手术，而不是更复杂的模型。

### 4.5 剩下的错误在哪里

最终方案共错 7,904 秒，约占 10.6%。其中 65% 落在 44 段持续 1 分钟以上的整段误判里，其余主要是工程分界的位置偏差。

最多的混淆是 81 判成 83（830 秒）、1 判成 7（507 秒）、83 判成 81（446 秒）、5 判成 0、0 判成 1、0 判成 5。这些都发生在"标注约定"的分界处。例如长空洞之后 81 到 83 的分界：分界前后 20 秒的画面几乎一样，区别要到镜头转向近端结肠时才出现。83 的起点是"开始吻合准备"这个意图，不是一个看得见的瞬间事件。12 个样本很难学准这种分界。

## 附录 C 怎么运行

以下命令在仓库根目录的 Windows 终端里运行。`<...>` 换成你自己的路径，输出目录必须是新目录。

1. 提取特征（约 20 分钟，单卡）：

```bat
scripts\temporal.bat cache-tokens --features <features.pt> --output-dir <特征目录>
```

2. 4 折交叉验证（约 45 分钟，单卡）。加 `--annotations` 时同时给出 Advanced 官方口径的分数：

```bat
scripts\temporal.bat cv --features <features.pt> --tokens <特征目录> --annotations <annotation_csv 目录> --output-dir <新目录>
```

`cv` 的主要输出：`summary.csv`（逐帧头、网络、只用顺序规则、最终方案四行），`fold_metrics.csv`，`video_metrics.csv`，`segment_metrics.csv`，`validation_predictions.csv`（最终方案的逐帧预测），`network_predictions.csv`（网络的直接输出，可以不重跑网络做解码实验），`result.json`（含每折读出的规则）。

## 附录 D 术语表

| 术语 | 含义 |
|---|---|
| 工程（阶段） | 手术中一个有明确目的的步骤，本任务共 13 类 |
| 1 fps | 每秒取一帧 |
| x（体外） | 镜头在体外的时间，画面被涂黑 |
| 空洞、长空洞 | 时间线上没有图片的秒。每个视频最长的那段叫长空洞 |
| ViT | Vision Transformer，把图片切成小块后用 Transformer 处理的视觉模型 |
| patch、patch token | 图片切成的 14×14 小块，以及它在网络里的向量 |
| CLS token | 加在所有 patch 前面、用来汇总整张图信息的特殊向量 |
| 自监督 | 不需要人工标签的预训练方法 |
| 冻结 | 只用模型提取特征，不更新它的参数 |
| z 分数 | 减去均值再除以标准差后的数 |
| 交叉拟合 | 每个样本的预测都来自没有见过它的模型 |
| 留一视频 | 每次留出一个视频，用其余视频训练 |
| logits、对数概率 | 分类器的原始分数，以及 softmax 之后取对数的值 |
| PCA、主成分 | 找出数据变化最大的方向，把高维数据投影到少数几个方向上 |
| 膨胀卷积 | 取样点之间隔几个位置的卷积，用少量层看到很长的范围 |
| 感受野 | 一个输出点能看到的输入范围 |
| 残差块 | 输出等于输入加上一个变换，便于训练深层网络 |
| LayerNorm | 对一个位置的所有通道做标准化 |
| 自注意力 | 每个位置按内容相似度对所有位置加权求和 |
| 相对位置偏置 | 按两个位置的距离给注意力加的可学习偏置 |
| 标签平滑 | 把训练目标从 0/1 改成略微平滑的分布，防止过分自信 |
| 数据增广 | 随机改变训练样本，增加多样性 |
| AdamW | 带权重衰减的 Adam 优化器 |
| 梯度裁剪 | 梯度过大时按比例缩小，稳定训练 |
| 种子集成 | 用不同随机种子训练多个模型，把输出取平均 |
| 嵌套交叉验证 | 外层折评估，内层折只在训练数据内部做选择 |
| Viterbi | 动态规划算法，精确求出得分最大的序列 |
| 先后规则、单段规则、最短块长 | 从训练视频读出的三类约束，见 3.9 |
| IoU | 交并比，交集大小除以并集大小 |
| 段级 F1@0.75 | IoU 不低于 0.75 才算匹配的段级 F1，见 3.10 |
| 宏 F1 | 每一类各算 F1 后取平均，不受类别大小影响 |
